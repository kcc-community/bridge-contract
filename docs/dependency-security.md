## Changes

Removed the unused Chainlink dependency and the separate `@openzeppelin/test-environment` environment. The four existing suites now use Truffle's own account and artifact facilities, preserving their test cases and assertions. Truffle, Ganache, the compiler and the package manager are explicitly versioned instead of relying on global tooling.

The legacy Git-sourced `ethereumjs-abi` dependency is replaced by its npm release. Narrow overrides update `form-data` and `bn.js` within their major versions, pin the root `elliptic` package, and keep Truffle and the test provider on the same Ganache release. The lockfile was generated by npm, not manually edited to hide findings. Moving deployment tooling into `devDependencies` is organizational; the security measurements still include it.

### OpenZeppelin compatibility correction

The previous `@openzeppelin/contracts@4.7.3` declaration is incompatible with the existing Solidity 0.7 source imports and compiler configuration. Version 3.4.2 restores that API. This is a compatibility downgrade, **not a security upgrade**, and it retains package-level advisories.

The successful build imported only `Ownable`, `SafeMath`, `ERC20`, `IERC20`, `Context` and `Pausable` from OpenZeppelin. The four OpenZeppelin findings in this audit concern initialization, `ERC165Checker` and `TransparentUpgradeableProxy`; those modules were absent from this compiled dependency graph. This is limited applicability evidence for this build, not a blanket safety finding and not a reason to dismiss future alerts automatically.

A move to a maintained OpenZeppelin major version requires a separately reviewed Solidity migration. Do not relax pragmas, change contract semantics or deploy newly built bytecode just to reduce an audit count.

## Remaining findings

The two critical package records are:

| Package | Remaining exposure |
| --- | --- |
| `elliptic` | Ganache carries its own bundled copy. Updating the root package does not replace that bundled implementation. Keep Ganache isolated to disposable local test accounts; this run did not verify production signing safety. |
| `tar` | A legacy transitive dependency remains vulnerable. A forced cross-major replacement was not applied without validating its consumers. |

The full audit also retains high and moderate findings in the legacy toolchain and the OpenZeppelin package. The evidence artifact contains `audit-before.json`, `audit-candidate.json`, `security-summary.json`, source hashes and installation/build/test logs. Artifacts have finite retention; the workflow creates a fresh audit artifact on subsequent runs.

The next substantive remediation is to replace the remaining legacy tooling and validate its replacements, not to exclude development dependencies, remove lockfile entries or dismiss every alert as irrelevant.

## Reproduce and maintain

Use Node 22.22.2 or newer within the 22.x line:

```sh
nvm install
nvm use
npm install --global npm@12.0.2
npm ci
npm run compile
npm test
npm run audit:dependencies
```

The final audit command intentionally returns a nonzero exit code while advisories remain. Ganache may fall back from its optional native uWS binary to its JavaScript implementation on Node 22; the validated tests passed with that fallback.

CI uses read-only repository permissions, no persisted checkout credentials and no deployment secrets. Installation, compilation and tests must succeed. The audit step reports all findings and emits a warning; it is informational while the documented legacy findings remain. **Passing CI does not mean vulnerability-free.** The temporary migration and write-enabled workflow were removed after the validated files were committed.

Dependabot configuration separates contract-library security PRs from tooling security PRs. Routine npm version-update PRs are disabled to avoid unrelated legacy-toolchain churn; security-update PRs are not disabled by that limit. The weekly schedule is not an email-notification schedule. This change neither dismisses existing alerts nor changes personal GitHub email preferences. Repository security-update settings and the exact post-merge Dependabot alert count must be checked separately.
